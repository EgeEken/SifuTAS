# SifuTAS agent instructions

- Work on `testing` only. Never modify, merge into, or release `main` without explicit authorization.
- Commit and push completed development passes to `testing` when the user authorizes the pass; report the commit SHA.
- Never launch, close, kill, or control Sifu. Runtime gameplay tests are performed manually. Check only whether Sifu is running before deployment; skip deployment if it is.
- Standing authorization permits replacing only the established Steam SifuTAS test DLL, after confirming it is a known SifuTAS build, Sifu is closed, a rollback copy is hash-verified, the new DLL matches the local artifact, and `SifuTAS.ini` is preserved. Stop if any check fails or the installed DLL may belong to another mod.
- SifuTAS is now a focused single-player time-control mod: speed selection/presets, pause, world-tick stepping, the fixed fullscreen GUI, configurable inputs, and an optional speed indicator. Do not resume savestates, recording/replay, reset tracing, actor inventories, multiplayer or networking, or diagnostic systems as features.
- Preserve the existing multiplicative `GetEffectiveTimeDilation` behavior and gameplay-state safety checks. Do not overwrite Sifu's stored dilation values or claim deterministic frame accuracy. A requested step is a `UWorld::Tick`, not a verified full simulation frame.
- The GUI toggle is reserved F1. Configurable bindings must use the local `APlayerController::InputKey` hook to suppress matching bound keys from gameplay; if safe interception cannot be installed, fail closed rather than allowing conflicting hotkeys through. Do not use global input hooks. With the GUI closed, ordinary mouse movement and unbound input must pass through unchanged.
- Persist the time-control settings in the versioned `[time_control]` section of `SifuTAS.ini`. Preserve old sections and migrate old binding layouts by applying current defaults, never reinterpreting old indices. Perform Unreal reflection/FName operations on the game thread.
- Keep the executable fingerprint checks, matching-PDB workflow, DLL/proxy infrastructure, ImGui/D3D11 integration, and upstream license/attribution. Remove abandoned systems from runtime/build targets without a risky wholesale rewrite of the imported source tree.
- Never commit or upload proprietary game executables, PDBs, game assets, saves, logs, local config, or user-specific paths. Use the installed Steam UE4.26 PDB for builds when available.
- Do not claim in-game behavior based on a successful build or offline test. Report what was built and tested separately from what still needs the user's manual acceptance test.
